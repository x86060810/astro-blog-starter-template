之前分享过一批 Windows 激活码，不少读者反馈已经失效。激活码有使用次数限制，被抢先使用就作废，这也是它天然不稳定的原因。

这次换个思路：不依赖激活码，用 **KMS 激活**的方式解决 Windows 与 Office 的授权问题。

## KMS 到底是什么

KMS 全称 Key Management Service，即密钥管理服务，是微软自己提供的一套授权机制。

它的设计初衷是面向企业、学校这类**批量部署**场景：在内网架设一台 KMS 服务器，客户端定期向服务器"报到"完成验证，就不必逐台输入密钥。

所以从原理上说，KMS 激活并不是破解手段，而是微软官方认可的技术路径。区别只在于：正规用法是企业自建 KMS 服务器并购买批量授权；而网上流传的做法，是连接到他人搭建的 KMS 服务器完成验证。

## 使用前必须知道的三件事

1. **这不是官方授权渠道。** 连接第三方 KMS 服务器，本质是借用他人的验证服务，企业环境使用存在合规风险，微软也可能判定为未授权激活。
2. **第三方服务器不一定可靠。** 这类域名可能随时关停，也可能被植入恶意内容，不建议在存有重要数据或办公账号的电脑上操作。
3. **适合个人测试与临时装机，长期使用建议走正规授权。** 本文的作用是应急方案，不是替代购买。

能接受以上前提，再继续往下看。

## 操作步骤

### 第一步：以管理员身份打开命令提示符

打开 `C:\Windows\System32` 目录，找到 `cmd.exe`，**右键选择"以管理员身份运行"**。

这一步很多人会做错：直接按 `Win + R` 输入 cmd 打开的是普通权限窗口，后面的命令必然执行失败。

### 第二步：输入激活命令

在命令窗口粘贴下面这条命令并回车：

```bat
slmgr /skms kms.v0v.bid && slmgr /ato
```

这条命令实际做了两件事：

- `slmgr /skms kms.v0v.bid`：把系统的 KMS 服务器地址指向 `kms.v0v.bid`
- `slmgr /ato`：立即向该服务器发起激活请求

执行成功后，会依次弹出两个提示框，分别提示"密钥管理服务计算机名已成功更新"和"产品已成功激活"。

### 第三步：确认激活状态

想核实是否真正激活，再执行：

```bat
slmgr /dlv
```

在弹出的详细信息窗口中，查看"许可证状态"是否显示为**已授权**。也可以直接打开"设置 → 系统 → 激活"页面确认。

## 常见报错与排错

### 1. 提示"无法联系 KMS 服务器"（0xC004F074）

说明客户端连不上服务器，常见原因有三种：

- 没有以管理员身份运行，权限不足
- 网络不通或被防火墙拦截，可先用 `ping kms.v0v.bid` 测试连通性
- KMS 服务器本身已关停，只能换一个可用地址重试

### 2. 提示命令语法错误

检查是否混入了中文标点。命令中的 `&&`、`/` 都必须是英文半角符号，复制粘贴时最容易被输入法带成全角字符。

### 3. 激活成功，过一段时间又提示未激活

KMS 激活具有**周期性**：客户端需要定期重新验证。正常联网时系统会自动续期；长期离线则可能到期失效，联网后重新执行 `slmgr /ato` 即可恢复。

### 4. 想恢复未激活状态

如果激活后需要撤销，依次执行：

```bat
slmgr /upk
slmgr /ckms
```

前者清除产品密钥，后者解除 KMS 服务器绑定。

## 小结

这套方法的优点是**零成本、一条命令、可重复使用**，尤其适合旧电脑重装系统后临时使用。

但要清楚它解决的是"能不能用"，不是"合不合规"。公司电脑、需要接受正版软件审计的设备，或者作为生产力工具长期使用的机器，仍然建议购买正式授权——省下的那点成本，不值得承担后续的合规风险。
